OBJETIVO PRINCIPAL

Realiza una auditoría arquitectónica de nivel élite sobre todo el proyecto y determina cuál sería la arquitectura óptima profesional si el objetivo fuera maximizar:

* Mantenibilidad
* Escalabilidad
* Rendimiento
* Modularidad
* Legibilidad
* Capacidad de evolución futura
* Velocidad de desarrollo
* Robustez técnica

Debes analizar el proyecto completo como lo haría un arquitecto de software senior especializado en aplicaciones complejas y videojuegos de larga evolución.

IMPORTANTE

No busques dividir archivos por tamaño.

No busques crear más archivos porque sí.

No busques una microfragmentación artificial.

Toda propuesta deberá estar justificada por una mejora real y objetiva.

Si una parte está correctamente diseñada, debe permanecer intacta.

PRIMERA FASE: AUDITORÍA COMPLETA

Analiza:

* Estructura de carpetas
* Flujo de dependencias
* Componentes
* Páginas
* Reducers
* Hooks
* Servicios
* Utilidades
* Datos estáticos
* Gestión de estado
* Ciclo principal del juego
* Sistemas de UI
* Integración Electron
* Persistencia
* Sistemas de audio
* Sistemas de IA
* Sistemas de eventos
* Sistemas de combate
* Sistemas económicos
* Sistemas diplomáticos

Identifica:

* Acoplamiento excesivo
* Responsabilidades mezcladas
* Archivos monolíticos
* Código duplicado
* Dependencias innecesarias
* Componentes demasiado grandes
* Reducers demasiado densos
* Lógica de negocio incrustada en UI
* Riesgos futuros de escalabilidad

SEGUNDA FASE: ANÁLISIS DE CADA ARCHIVO GRANDE

Para cada archivo relevante:

* Tamaño aproximado
* Complejidad funcional
* Responsabilidades actuales
* Nivel de cohesión
* Nivel de acoplamiento

Determina:

* Si debe mantenerse intacto
* Si debe dividirse parcialmente
* Si debe dividirse profundamente
* Si debe migrarse a una arquitectura diferente

Explica siempre el motivo.

TERCERA FASE: ARQUITECTURA ÓPTIMA TEÓRICA

Diseña la mejor arquitectura posible para este proyecto considerando:

* Estado actual
* Evolución futura
* Coste de mantenimiento
* Coste de desarrollo
* Rendimiento

Propón:

* Estructura de carpetas ideal
* Estructura de módulos ideal
* Separación de dominios
* Separación de servicios
* Separación de lógica de negocio
* Separación de presentación

CUARTA FASE: ANÁLISIS DE FRAGMENTACIÓN ÓPTIMA

Evalúa cada módulo y determina el nivel óptimo de granularidad.

Debes indicar claramente:

* Qué debe permanecer unido
* Qué debe dividirse en submódulos
* Qué debe dividirse en múltiples niveles
* Qué no debe tocarse

NO existe límite de fragmentación.

Sin embargo:

* No debes fragmentar si no aporta beneficios reales.
* Debes evitar sobreingeniería.
* Debes evitar arquitecturas innecesariamente complejas.

Busca el punto óptimo real.

QUINTA FASE: OPTIMIZACIÓN DE RENDIMIENTO

Analiza:

* Re-renderizados
* Flujo React
* Dependencias
* Reducers
* Ticks
* Bucles
* Cálculos repetidos
* Memorización
* Carga inicial
* Lazy loading
* División de bundles
* Componentes pesados

Indica:

* Problemas detectados
* Impacto estimado
* Solución propuesta
* Prioridad

SEXTA FASE: PLAN DE REFACTORIZACIÓN PROFESIONAL

Genera un roadmap completo dividido en:

FASE 1 - Ganancias rápidas
FASE 2 - Mejoras estructurales
FASE 3 - Modularización avanzada
FASE 4 - Arquitectura de largo plazo

Para cada acción:

* Beneficio esperado
* Riesgo
* Complejidad
* Prioridad
* Retorno de inversión técnico

SÉPTIMA FASE: VEREDICTO FINAL

Responde claramente:

* ¿La arquitectura actual es buena?
* ¿La arquitectura actual es escalable?
* ¿Existen riesgos futuros?
* ¿Qué partes son excelentes y no deben tocarse?
* ¿Qué partes requieren refactorización?
* ¿Qué cambios producirían el mayor beneficio?
* ¿Qué cambios serían sobreingeniería y deben evitarse?

CRITERIO MÁXIMO

No busco la mayor cantidad de archivos.

No busco la mayor cantidad de capas.

No busco la mayor complejidad arquitectónica.

Busco la arquitectura profesional óptima que produzca la máxima eficiencia real con la menor complejidad posible.

Debes actuar como un arquitecto principal encargado de preparar el proyecto para años de crecimiento continuo y determinar el punto exacto donde la modularidad aporta valor y donde empieza a convertirse en sobreingeniería.
